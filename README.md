# DRB Decision Journey — 80년의 여정, 그리고 다음

2026 DRB 신규입사자 온보딩 · 조별 경영 시뮬레이션 게임

> 이 문서는 **개발자가 아닌 People팀 담당자**가 읽고 직접 운영·수정할 수 있도록 썼습니다.
> 코드를 몰라도 됩니다. 순서대로 따라오시면 됩니다.

---

## 1. 이 게임이 하려는 것

각 조가 **1945년부터 2026년까지** 한 회사를 경영합니다. 결과를 모르는 채로 6번 결정합니다.

```
시대 진입 (산업 브리핑 · 전망 선명도)
  → 상황 확인 (조별 4가지 관점으로 토론)
  → 자원 배분 (해외는 '어디에 / 어떤 방식으로'까지)
  → 경영정책 결정
  → ⏱ 시간 진행 — 우리와 다른 조와 시장이 함께 움직이는 것을 봅니다
  → 결과 (왜 이렇게 됐는지 · 지도)
  → ACTUAL DRB (실제 DRB / 같은 산업 다른 회사)
  → …3개 시대 반복…
  → 2026 · 결과가 없는 시대
  → 최종 결과 · 변화 대응력 공개 → 회고
```

**최종 메시지는 이것입니다.**
> 좋은 경영은 미래를 정확히 맞히는 것이 아니라,
> 변화가 왔을 때 다시 선택할 수 있는 힘을 만드는 것이다.

### 3개 시대 (실제 DRB 연표에 맞춰져 있습니다)

| 시대 | 연도 | 핵심 질문 | 선택지 | 토론시간 | 전망 선명도 |
|---|---|---|---|---|---|
| ERA 1 | 1945~1978 (1947 · 1965) | 고무신인가, 벨트인가 | 6개 | 5분 | 85% |
| ERA 2 | 1966~2004 (1986 · 1997) | 어디까지 넓힐 것인가 | 8개 | 4분 | 58% |
| ERA 3 | 2005~2026 (2012 · 2026) | 얼마나 빨리 변화할 것인가 | **10개** | 3분 | **30%** |

타임라인은 `1947 → 1965 → 1986 → 1997 → 2012 → 2026` 입니다.
실제 DRB 연표의 분기점(1947 전동벨트 / 1965 KS 획득 / 1986 연구소 설립 / 1997 IMF / 2012 기업분할)에 맞췄습니다.

시대가 갈수록 **연도 간격이 좁아지고, 시간은 짧아지고, 정보는 많아지고, 전망은 흐려집니다.**
"세상이 빨라졌다"고 설명하지 않고 게임 구조로 느끼게 하는 장치입니다.

- **3개 시대 × 2 국면 = 6번의 의사결정**, 약 45분
- **뒤로 갈수록 결정할 것이 늘어납니다** (선택지 6 → 8 → 10개)
- 조는 3~6개까지 설정 가능 (기본 4조)
- **순위를 매기지 않습니다.** 같은 조건에서 서로 다른 회사가 되는 것이 목표입니다.

> ⚠ 게임 속 상황 글은 **그 시기 고무산업이 놓여 있던 일반적인 상황**입니다.
> **실제 DRB 연혁은 `data/actual_drb.js` 에 사사(社史) 자료 그대로 입력되어 있습니다**
> (ERA1 13건 · ERA2 14건 · ERA3 12건의 연표). ACTUAL DRB 화면에서만 표시됩니다.

## 2. 이 게임의 특징 4가지

### 2-1. 경쟁은 참여한 조들끼리만 합니다

**AI 경쟁사는 없습니다.** 예전에는 세 곳이 같은 엔진으로 함께 경영했는데, 재보니
숫자를 하나도 바꾸지 못했습니다 — 조들이 늘 생산능력에 막혀 있어서(24번 중 20번),
경쟁사가 수요를 깎아도 `sold = min(수요, 생산능력)` 에서 통째로 흡수됐습니다.
경쟁사 3곳 / 1곳 / 0곳의 최종 매출이 **완전히 같았습니다.** 화면에만 있고 게임에는
없는 것이라 뺐습니다.

조들이 서로 부딪히는 자리는 둘입니다.

- **3국면 자동차 공동개발** — 한 곳만 계약합니다. 조건을 넘긴 조가 여럿이면
  그중 한 조만 따고, 나머지는 개발비만 쓰고 물량을 못 받습니다.
- **몰림(crowding)** — 같은 분야에 여러 조가 몰리면 그 시장이 나빠집니다.
  ⚠ 다만 지금은 조들이 대부분 생산능력에 막혀 있어 이 효과가 잘 드러나지 않습니다.

### 2-2. 해외는 '어디에 / 어떤 방식으로'까지 정합니다 (ERA 2부터)

| 어디에 | 특징 |
|---|---|
| 중국 | 시장이 크지만 단가 싸움이 심함 |
| 동남아 | 원가 최저, 인프라·숙련도 부족 |
| 북미 | 단가를 잘 쳐주지만 요구가 높고 비쌈 |
| 유럽 | 기술 인증 문턱이 높음, 넘으면 오래감 |

| 어떤 방식 | 비용 | 효과 | 가동까지 |
|---|---|---|---|
| 수출 | 낮음 | 작음 | 즉시 |
| 판매거점 | 중간 | 중간 | 1국면 |
| 합작(JV) | 중간 | 큼 (성과는 나눔) | 1국면 |
| 직접 생산법인 | 높음 | 가장 큼 | **2국면** · 경직성↑ |

거점은 **검토 → 건설 중 → 가동** 으로 자라며, 세계지도에 표시됩니다.
우리가 만든 거점이 지도에 찍힙니다.

### 2-3. 변화 대응력 (Adaptive Capacity)
**게임 내내 숨겨져 있다가 마지막에만 공개되는 지표**입니다.

- 만드는 것 : 현금 여력 · 기술 옵션 · 고객 다변화 · 공급망 유연성 · 인재 · 해외 포트폴리오 · 실험 경험
- 없애는 것 : 경직성 · 조직 피로

최종 화면에서 **현재 경쟁력**과 **변화 대응력**을 나란히 보여줍니다.
"지금 잘 되는 회사"와 "앞으로 움직일 수 있는 회사"가 다르다는 것을 숫자로 보게 됩니다.

### 2-4. 돌발상황이 시간 진행 중에 속보로 뜹니다
결정을 확정하면 화면에 시간이 흐르고, 그 도중에 사건이 **뉴스 속보처럼** 오른쪽 위에 등장합니다.
- 노란 테두리 = 산업 전체에 벌어진 일
- 빨간 테두리 = **우리 회사에만** 벌어진 일 (품질 클레임, 인력 이탈 등)

### 2-5. 2026년에는 결과가 없습니다
지금까지 다섯 번은 `결정 → 시간 진행 → 결과` 였습니다.
2026년의 마지막 결정 뒤에는 **시간 진행 버튼이 사라집니다.**

```
2026 ━━━━━━━━━━ ?

지금까지 여러분은 결과가 이미 존재하는 시대를 경영했습니다.
하지만 2026년 다음에는 아직 결과가 없습니다.
```

시장은 계속 움직이는 것으로 보여주고, 마지막 버튼은 `다음 선택으로` 입니다.

> ⚠ **진행자는 이 연출을 미리 말하지 마세요.** 이 게임의 클라이맥스입니다.

## 3. 실행 방법

### Cloudflare Pages 에 올리기 (사내 PC 부담 없이)
1. **`배포파일 만들기.bat`** 더블클릭 → `_deploy` 폴더 생성
   (게임 파일만 복사됩니다. 기획서와 DRB 역사 자료는 빠집니다)
2. https://dash.cloudflare.com → **Workers & Pages → Create → Pages → Upload assets**
3. `_deploy` 폴더를 통째로 드래그 → Deploy
4. `프로젝트명.pages.dev` 주소로 각 조가 접속

> ⚠ **`data/actual_drb.js` 에 DRB 실제 역사가 들어 있습니다.**
> Pages 는 기본이 전체 공개이므로, 사내 자료라면 **Cloudflare Access**(무료·50명)로
> 이메일 인증을 걸어야 합니다. 회사 보안 기준을 먼저 확인하세요.

### 가장 쉬운 방법
**`게임 실행.bat`** 를 더블클릭합니다. 검은 창이 뜨고 브라우저가 자동으로 열립니다.

> ⚠ **검은 창을 닫지 마세요.** 이 창이 서버입니다. 교육이 끝나면 그때 닫습니다.

### Python이 없는 PC라면
`index.html` 을 더블클릭해도 그대로 돌아갑니다. 설치할 것이 없습니다.

### 여러 조가 각자 기기로 접속하려면 — 라이브 세션 권장
1. 진행자 PC에서 **배포 주소를 그대로** 엽니다. (진행자 화면이 첫 화면입니다. 조는 `/play` 로 들어갑니다)
2. `교육 세션 만들기` → 참가 조 수를 선택합니다.
3. 화면에 만들어진 **조별 전용 링크를 해당 조에만** 전달합니다. 링크에는 그 조의 최초 참가키가 포함되므로 조끼리 바꾸어 전달하지 않습니다.
4. 각 조는 받은 링크로 접속하고 조 이름을 확인한 뒤 게임을 시작합니다.
5. 진행자는 같은 탭을 유지하면서 조별 연결·결정 상태를 확인하고 공개 단계를 제어합니다.

라이브 세션에서는 서로 다른 PC·태블릿의 진행 상황이 진행자 화면에 약 15초 안에 모입니다. 참가자는 진행자가 돌발상황, DRB 기록, 다음 공통 배경을 공개할 때까지 대기 화면을 보게 됩니다.

> **혼자 리허설할 때 — 한 PC에서 여러 조를 띄워도 됩니다.**
> 탭을 새로 열어 각 조의 코드를 넣으면 탭마다 다른 조가 됩니다. 조 인증 정보는
> 탭별(`sessionStorage`)로 갖고 있어 서로 덮어쓰지 않습니다.
> 단 **같은 탭에서 다른 조 코드를 넣으면 그 탭이 새 조로 바뀝니다.** 조마다 탭을 따로 여세요.
> (게임 저장은 탭끼리 공유되므로, 리허설 중 탭을 새로고침하면 그 탭의 진행은 사라집니다.
> 라이브 세션은 원래 이어하기를 지원하지 않습니다)

> 사내 Wi-Fi와 배포 주소 접속은 **교육 전날 현장에서 반드시 테스트하세요.** 라이브 연결을 쓸 수 없는 경우에는 각 기기에서 오프라인으로 플레이한 뒤 `결과 코드`를 진행자 화면에 수동으로 추가할 수 있습니다. 결과 코드는 장애 대응용 보조 수단이지 기본 운영 방식이 아닙니다.

### 사내망에서 로컬로만 실행하려면
1. 진행자 PC에서 `게임 실행.bat` 실행
2. 진행자 PC의 IP 확인 (명령 프롬프트에서 `ipconfig`)
3. 각 조 기기에서 `http://그IP:8765/index.html`

이 방식은 게임 파일을 사내망에서 여는 방법입니다. Cloudflare 라이브 세션을 만들지 않으면 각 브라우저의 상태는 자동으로 합쳐지지 않습니다.

### 무료 서버에 올리려면
전부 정적 파일이라 Netlify · Cloudflare Pages · GitHub Pages 등에 **폴더째 올리면 그대로 동작**합니다.

## 4. 진행 방법

### 4-1. 게임 시작
1. 참가 조 수(3~6조) 선택 → 2. 우리 조 선택 → 3. `게임 시작`

### 4-2. 한 국면 진행하는 법
| 순서 | 하는 일 |
|---|---|
| 1 | 산업 브리핑과 전망 선명도를 읽어줍니다 |
| 2 | **4가지 관점**(시장·기술·재무·고객)으로 각자 한 번씩 말하게 합니다 |
| 3 | 조원끼리 토론 (상단 타이머가 시대별로 줄어듭니다) |
| 4 | **테이블 위 실물 토큰을 먼저 옮깁니다** |
| 5 | 토큰과 똑같이 화면에 입력 (해외면 지역·방식도) |
| 6 | 경영정책 선택 → `결정 확정 · 시간 진행` |
| 7 | 타임랩스를 함께 봅니다 (급하면 `건너뛰기`) |
| 8 | 결과 확인 — 왜 이렇게 됐는지, 다른 조는 뭘 했는지 |

### 4-3. 진행자가 챙길 것
- **ERA 2부터 해외 선택이 열립니다.** 지역·방식을 안 고르면 효과가 절반으로 줄어든다고 알려주세요.
- **ERA 3은 선택지가 10개**입니다. 다 볼 수 없다는 점, 무엇을 볼지 고르는 것도 결정이라는 점을 짚어주세요.
- **현금이 마이너스여도 게임은 계속됩니다.** 설비를 팔아 버티고, 회사는 작아지지만 계속 결정합니다.

### 4-4. 진행자 화면 — 라이브 퍼실리테이션 콘솔
배포 주소를 그대로 **진행자 PC와 빔프로젝터**에 띄웁니다. 이 화면은 점수를 감시하는 대시보드가 아니라, 모든 조에 같은 정보를 같은 순서로 공개하는 교육용 콘솔입니다.

한 국면은 다음 여섯 단계로 운영합니다.

| 단계 | 진행자 화면에서 확인·공개할 것 |
|---|---|
| 1. 공통 배경 | 당시의 산업환경, 정보량, 전망 선명도, 제약조건을 전 조에 똑같이 설명 |
| 2. 조별 결정 | 확정 여부, 투자 배분, 정책, 지역·진입 방식 같은 추가 판단, 남긴 현금을 비교 |
| 3. 돌발상황 | 모든 조가 결정한 뒤 같은 헤드라인과 공통 충격을 동시에 공개 |
| 4. 결과·반응 | 같은 사건이 각 조의 누적 선택에 따라 어떻게 다르게 전달·적용되었는지 확인 |
| 5. DRB 실제 선택 | 먼저 참가자의 판단을 말하게 한 뒤 확인된 DRB 기록을 공개하고 비교 |
| 6. 토론 | 선택의 가정·대가·축적된 역량을 질문하고 한 문장 교훈을 정리 |

토론이 끝나면 `다음 국면 →` 을 눌러야 참가자 화면에 **다음 공통 배경**이 열립니다. 진행자가 공개하기 전에는 미래 배경, 돌발상황, DRB 기록이 참가자에게 먼저 보이지 않습니다.

`산업 지도`에서는 조별 거점의 **검토 → 건설 중 → 가동** 상태와 산업의 이동을 함께 볼 수 있습니다. 결정 표와 지도는 순위를 매기기 위한 것이 아니라, 같은 배경에서 왜 서로 다른 회사가 만들어졌는지 묻는 근거로 사용합니다.

라이브 연결이 완전히 불가능할 때만 각 조의 `결과 코드 복사` → 진행자 화면 `결과 코드 받기`를 사용합니다.

> 진행 방법과 시대 배경 설명, 조에게 던질 질문은 **`진행자 가이드.md`** 에 따로 정리했습니다.

### 4-5. 계산 근거 확인 (관리자 모드)
오른쪽 위 `관리자` 버튼 → 결과 화면에 **모든 지표가 왜 그만큼 변했는지** 항목별 근거가 나옵니다.

## 5. 내용 수정하기

모든 교육 내용은 **`data` 폴더 안 11개 파일**에 있습니다. 진행 방법은 `진행자 가이드.md` 에 있습니다. `js` 폴더는 건드릴 필요가 없습니다.
**VS Code** 같은 편집기로 열어 **UTF-8**로 저장하세요.

| 파일 | 무엇을 바꾸나 |
|---|---|
| `config.js` | 조 수, 시작 자원, 토큰 단위, 난이도, 조별 관점 |
| `진행자 가이드.md` | ⭐ **진행 방법 · 시대 배경 · 경영 개념 · 조에게 던질 질문** |
| `eras.js` | 시대 · 산업 브리핑 · **시대 속도 · 전망 선명도** |
| `rounds.js` | 시대별 국면 구성, 상황 글, **타임라인 연도**, 예산 |
| `investments.js` | 투자 항목과 효과 |
| `policies.js` | 경영정책 |
| `events.js` | 돌발상황 |
| `global.js` | **해외 국가 · 진출 방식** |
| `actual_drb.js` | ⭐ **실제 DRB 사례** + 경영스타일 |
| `competitors.js` | ⭐ **실제 경쟁기업의 선택** |

> 수정 후 브라우저에서 **Ctrl+F5**(강력 새로고침).

### 5-1. 시대 속도 바꾸기 — `eras.js`
```js
pace: { yearsPerSubround: 18, discussSeconds: 300 },   // 담당 기간 / 토론 시간
visibility: 85,                                         // 전망 선명도 (0~100)
visibilityNote: "산업의 방향이 단순합니다. 멀리 보고 크게 결정할 수 있습니다.",
```
**뒤 시대일수록 세 값이 모두 작아지도록** 유지하세요. 이것이 "빨라진다"의 정체입니다.

### 5-2. 타임라인 연도 — `rounds.js`
```js
{ id: "r1s1", year: 1947, ... }
```
현재 `1947 → 1965 → 1986 → 1997 → 2012 → 2026`.
**실제 DRB 연표의 분기점**에 맞춰져 있습니다.
(1947 전동벨트 생산 / 1965 KS 획득 / 1986 연구소 설립 / 1997 IMF / 2012 기업분할)

연도를 바꾸려면 여기 `year` 와 `eras.js` 의 `yearLabel`·`span`,
`actual_drb.js` 의 `year` 세 곳만 고치면 됩니다. 게임 로직은 연도를 계산에 쓰지 않습니다.

### 5-3. 산업 브리핑 — `eras.js`
```js
briefing: {
  title: "1970s–90s INDUSTRY OUTLOOK",
  domestic: [ { tone: "up", text: "제조업 설비투자 급증" },     // up=▲ down=▼ q=? flat=·
              { tone: "q",  text: "자동차산업 태동 — 물량은 아직 작음" } ],
  global:   [ { tone: "up", text: "세계적으로 자동차 보급 확대" } ],
  risk:     [ "고객 요구 수준이 빠르게 높아진다" ]
}
```
> ⚠ **그 시점에 알 수 있었던 것만** 적으세요. 미래 결과를 넣으면 게임이 성립하지 않습니다.
> 뒤 시대일수록 `q`(물음표)를 늘리고 항목 수도 늘리세요.

### 5-4. 투자 항목 — `investments.js`
```js
{
  id: "globalPlant",
  role: "future",              // 몰림(같은 분야에 몇 조가 걸었나) 계산에 쓰는 태그
  newField: true,              // '해보지 않은 분야' (본업집중 정책이 효율을 깎음)
  name: "해외 생산거점",
  dimensions: ["where", "how"],  // ← 있으면 '어디에/어떻게' 선택 UI가 열립니다
  tradeoffs: [ { type: "later", text: "..." }, { type: "minus", text: "..." } ],
  perUnit: {
    now:   { quality: 0.48 },   // 이번 국면 즉시
    next:  { capacity: 0.55 },  // 다음 국면
    later: { demandBonus: 0.5 },// 두 국면 뒤
    stock: { rdStock: 1.0 },    // 쌓였다가 임계를 넘으면 터짐
    mult:  { unitCost: -0.007 } // 이번 국면 배율
  }
}
```

쓸 수 있는 지표:
`cash` `capacity` `tech` `quality` `trust` `people` `reach` `fatigue` `rdStock`
`demandBonus` `exposure` `shield` `flex`(유연성) `rigidity`(경직성) `experiments`(실험)

`role` 값: `capacity` `quality` `tech` `demand` `future` `people` `flex` `cash`

### 5-6. 난이도 조절 — `config.js`
| 증상 | 고칠 곳 |
|---|---|
| 너무 쉽게 돈을 번다 | `engine.baseUnitCost` ↑ (0.60 → 0.66) |
| 너무 빨리 망한다 | `engine.revenueScale` ↑ (4.0 → 4.4) |
| 후반에 다들 적자다 | `eras.js` 의 후반 `demand` ↑ 또는 `laborCost` ↓ |
| 큰 조가 독주한다 | `engine.sizeCostWeight` ↑ (260 → 340) |
| 망한 조가 회복을 못 한다 | `engine.rescueBelow` ↑ (-30 → -10) |
| 기술이 너무 빨리 오른다 | `engine.rdStockPerTech` ↑ (34 → 40) |
| 변화 대응력이 다 낮게 나온다 | `engine.js` 의 `adaptiveCapacity` 배점 조정 |

### 5-7. ⭐ DRB 실제 사례 — `actual_drb.js`
현재 5개 시대 모두 `[DRB 실제 사례 입력 예정]` 입니다.

```js
  choice:    "DRB가 실제로 내린 선택",
  result:    "그 선택이 가져온 실제 결과",
  image:     "assets/img/r2s1.webp",
  note:      "진행자가 읽어줄 짧은 설명",

```

> ⚠ **추측해서 채우지 마세요.** 사내 자료 · 사사(社史) · 경영진 인터뷰로 확인한 사실만.
> ⚠ **ERA 5(2020년대)의 `result` 는 단정하지 마세요.** 아직 결과가 나오지 않은 구간입니다.

### 5-8. ⭐ 경쟁기업 실제 선택 — `competitors.js`
같은 산업의 다른 회사들이 그 시대에 무엇을 했는지. **검증된 자료만.**
비워두면 `[입력 예정]` 으로 표시되고 게임은 정상 진행됩니다.
목적은 "누가 옳았나"가 아니라 **각 선택이 그 회사를 어떤 회사로 만들었는가** 입니다.

### 5-9. 이미지 — `assets/img/`
파일을 넣고 `rounds.js` / `actual_drb.js` 의 `image:` 에 경로를 적습니다.
없으면 점선 상자로 자리만 표시되고 게임에는 지장이 없습니다.
필요한 이미지와 **생성 프롬프트**는 `assets/이미지_요청서.md` 에 있습니다.

> **ACTUAL DRB 화면의 이미지는 AI 시대 연출 자료입니다.** 실제 DRB 사진이 아니며, 화면 배지와 캡션으로 이를 명확히 고지합니다.

## 7. 데이터는 어디에 저장되나

운영 방식에 따라 다릅니다.

### 오프라인 실행
라이브 세션 링크 없이 실행한 게임 상태는 **각 PC의 브라우저 안(localStorage)** 에만 저장됩니다. 자동 서버 전송이나 다른 조와의 동기화는 없으며, 필요한 경우 사용자가 직접 결과 코드를 복사해 진행자에게 전달합니다.

### 라이브 세션
진행자가 `교육 세션 만들기`로 연 세션에서는 진행에 필요한 **최소 스냅샷만** Cloudflare Durable Object로 전송됩니다.

- 조 이름, 현재 국면·단계
- 투자 배분, 경영정책, 지역·진입 방식 등 추가 선택
- 돌발상황 적용·반응
- 교육 진행에 필요한 KPI, 현금, 거점 상태

참가자 브라우저는 **자기 조의 스냅샷만** 보냅니다. 다음 정보는 보내지 않습니다.

- 시대 체크포인트의 자유서술 답변(지킨 것·감수한 대가·배운 점)
- 이름, 사번, 이메일 등 개인정보
- 다른 조의 전체 게임 상태

라이브 세션 데이터는 생성 후 **24시간이 지나면 자동 삭제**됩니다. 교육에는 개인 이름 대신 `1조`, `2조`처럼 조 이름만 사용하세요.

## 9. 시뮬레이션 엔진은 어떻게 계산하나

```
수요 = (시대 시장규모 + 우리가 새로 연 수요기반)
       × 고객신뢰 × 판매망 × 기술적합도 × 경쟁강도 × 정책 × 돌발상황

실제 판매 = min(수요, 생산능력)         ← 만들 수 없으면 못 판다
매출     = 실제 판매 × 단가(품질·기술이 올려줌)
영업손익 = 매출 − 변동비 − 고정비(설비·인건비·규모 관리비)
```

여기서 나오는 성질:
- 수요가 커도 **설비가 없으면** 못 팔고, 납기를 못 지켜 신뢰가 깎입니다
- 설비가 커도 **신뢰·판매망이 없으면** 설비가 놉니다
- **R&D는 쌓여야** 기술이 도약합니다 (인력이 많을수록 빨리)
- **같은 분야에 여러 회사가 몰리면** 경쟁강도가 올라가 다 같이 어려워집니다
- **규모가 커지면** 관리비가 비선형으로 붙고 경직성이 올라갑니다 — *큰 기업은 강하지만 무겁다*
- **현금이 바닥나면** 설비를 팔아 버팁니다 — 작아지지만 오히려 가벼워집니다
- **같은 사건도** 그동안의 투자·정책·거점에 따라 회사마다 다르게 작용합니다

관리자 모드에서 이 모든 계산의 항목별 근거를 볼 수 있습니다.

## 10. AI에 대해

**이 게임에는 AI 경영참모가 없습니다.** (요청에 따라 제외했습니다)

AI라는 이름이 붙은 것은 이제 없습니다. 모든 계산은 외부 API가 아니라
`engine.js` 안의 규칙 기반 판단입니다. **인터넷 없이 완전히 동작합니다.**

경계는 이렇습니다.

| 하는 일 | 담당 |
|---|---|
| 매출 · 손익 · 지표 계산 | **반드시** `engine.js` (규칙 기반) |
| DRB 의 역사 | **사람이 입력한 데이터만.** 생성 금지 |

## 11. 지켜야 할 원칙

1. **사실과 연출을 명확히 구분합니다.** 금색 카드의 텍스트·연표는 확인된 실제 기록이며, 이미지는 AI 시대 연출 자료입니다.
2. **순위를 매기지 않습니다.** 조마다 다른 회사가 되는 것이 성공입니다.
3. **모든 선택에는 대가가 있어야 합니다.**
4. **숫자는 규칙이 정합니다.** AI가 결과를 만들지 않습니다.
